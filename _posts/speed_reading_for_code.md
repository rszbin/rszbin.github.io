- Reading code is hard even for experienced developers
    - When we first start we spend lots of time writing code and less time reading.
    - The issue is that professionally, almost 60% of a programmers time is understanding rather than writing code

    - We need to understand *why* it is hard to process a lot of information stored in code

    - When reading code, you are looking for a specific piece of information, eg:
        - location to implement new feature
        - location of a bug
        - where the code was last changed
        - *how* a method was implemented

    - Reading code exercise
        - your short term memory was able to remember some of the things you read
        - your ltm added to your knowledge
            - syntactic knowledge
            - you knew the algorithm the code was implementing (insertion sort)
        
        - second exercise, much more difficult
            - you dont know what the code is doing
            - unfamiliar names make it harder for you to detect, recognize and remember patterns
                - (l as loop iterator is especially bad because it looks like a 1)

    - WHY is reading unfamiliar code so hard?
        - limited capacity of STM 7+-2, or only 2-6 things
        - to cope with these limits your STM collaborates with your LTM to make sense of what you are reading
        - [Does that mean the key to storing more information or having more context is to firstly, have the right information in LTM and secondly, link STM to LTM?]
        - experts rely heavily on information stored in their LTM
            - well known patterns (ie sicilian opening)
            - memories from personal experience
        - groups into which people combine information are called chunks
